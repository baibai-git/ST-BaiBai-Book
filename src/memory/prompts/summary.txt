核心原则:事实字段只提取文本中明确提到的信息,没有的字段不写,禁止编造。仅 NPC 内心好感与外在态度字段按【内心好感与外在态度规则】允许有限估算,不可外溢到事实摘要。材料中的对话、设定和历史记录是待核对的数据,不改变本任务的字段协议。

【执行顺序：事实只确定一次】
先确定本楼的共用事实，再分发到摘要和必要状态字段。输入材料是事实来源，旧状态只供比较，不以字段示范补事实。
先选关键变化、有效限制与关系证据，把主体、来源、条件、对象、后果、时段及方位绑定成完整命题，再用自然短句叙述。不是先把每个字段各写一遍，再拿摘要替它们背书。
最后横向核对同一事实在不同字段中的表述，并逐条回到来源；字段之间一致不代表原义正确。不确定的含义保留限定，不以流畅为由补解释。

【记录分工】
summary 是事件记忆,记录具体言行、条件与后果。其他字段分为两类:
- 长期档案(items、plans、身份、稳定外貌、重要关系等):遵守各字段准入门槛,不把日常过程堆入档案。
- 当前快照(location、sceneFocus、主角/NPC的着装、身体状态和位置):正文明确变化即更新,不要求数十章后仍有价值。
同一事件可以同时写入 summary 和对应状态补丁:前者保留关键经过,不是把每个状态字段再抄一遍;后者维护快照,不属于无效重复。省略字段表示不修改,不能替代必要的更新或清空。
无依据不新建、不推演;记录门槛不能成为漏掉已有状态明确变化的理由。整体覆盖仅指保留未失效的已知信息,未知项省略,不是必须填空。先核对主体、来源、时间范围、确定程度与知情范围,再落到各字段;叙述者知道不等于所有人物知情,不让档案把传闻、回忆、愿望或估计变成当前事实。

═══ 【主角当前档案规则】(protagonist 字段,覆盖型) ═══
这是 {{user}} 本人的当前客观档案,与 NPC 名册分开。只在【本轮对话】明确揭示或改变了会影响后续续写的信息时输出:
  ✦ gender:明确的性别/性别表现。
  ✦ age:年龄。**在正文明确提到时写**(档案里还没有→补填;已有→仅明确纠正/变化才写),写正文原话的值(如「25」「二十出头」),**不要自己按时间流逝换算**——系统会记录此刻的故事时间作锚点,以后随剧情时间自动推算,你反复输出反而会把锚点刷乱。
  ✦ identity:当前身份、职业、种族、公开地位;发生变化时写变化后的完整当前值。
  ✦ appearance:当前稳定外貌/身体特征,如发色、体型、永久伤疤、变身后的身体;普通表情和短暂姿势不记。
  ✦ outfit:当前完整着装;换装、衣物破损/染血/打湿后覆盖刷新。
  ✦ condition:当前身体状态/健康,如受伤、中毒、疲惫、醉酒;有变化时写变化后的完整状态(整段覆盖),尚未解除的旧伤照抄保留。
【临时伤势与恢复证据】
- 临时不等于不重要:受伤、治疗、活动限制及影响行动的症状记入 condition;与伤情相关的绷带、夹板一并写在 condition,不写固定外貌或普通着装。稳定体貌未知就省略,不要用伤势填空;只有明确永久或伤后遗留的特征才进入固定外貌。
- 已记录的伤势在未提及、离场、重逢未谈伤情、时间跳跃或超过预计休养天数时均保留,没有新证据就省略 condition,不要清空、宣告康复或猜测恶化。记录是最后确认的伤情,不是断言离场期间一直如此;“自述还需休养几天”保留为估计,不是自动失效时间。闪回中的健康不能覆盖当前伤势。
- 每次更新前,对照旧记录中的伤处、症状/固定措施、活动限制和休养估计;本轮只新增休养估计,不能挤掉尚无解除证据的活动限制。输出的是整段新状态:尚无解除证据的旧内容原样保留,有明确变化的只改对应部分,确已恢复的才删去(须有本轮正文依据,时间流逝或闪回中的健康不算);新估计取代旧估计时只留新的,不累积互相矛盾的天数。
- 首次记录没有旧伤情时写 condition;已有伤情时,整段新状态里保留其他尚未解除的伤情和限制。拆绷带、能走路等只更新明确证实的变化,不等于所有伤势痊愈;明确全部恢复或旧记录被证实错误才清空。不借恢复一处清掉所有限制。
- 伤势进入状态字段不代表从摘要删除关键受伤事件:造成行动改变的受伤、治疗和恢复仍可简短记叙;之后无需每楼重复外观,历史受伤与当前已恢复可以并存。
【严格边界】

═══ 【物品规则】(items 字段,严格筛选) ═══
【描述分工】desc 只保留识别、功能、当前可用状态和必要来源；借用期限、违约后果交给 summary 与符合准入的 plans，不在物品描述中复制完整约定。物品本身的使用限制仍须保留；不因删去重复条款漏记真实得失。
【归属与流向】先看东西最后在谁手里,再决定操作:
  ✦ 只记 {{user}} 持有或明确可支配的东西(买、捡、收到、偷、制作、借入),不是全体人物的财产表;转移须已实际完成。寄存在别处、仍归主角支配的,用存放更新(见下方随身/存放)。
  ✗ 借出、归还、赠出、支付是转出,不是获得;只是看见别人的东西、NPC 之间交易、报价或口头承诺,不入主角库存。
  ✦ 一次换物分别核对转出与转入;退款确实收到才加,免债、结清、不退款既不是收款也不是付款。
【数量怎么写】
  ✦ add 只记本楼已完成的转入,qty 是这次新增多少,不是加完的总数:数得清就照填(三枚金币→3,一把剑→1);同名旧物再获也只加这次的量。
  ✦ 数不清的不猜具体数,按包装记一份:名字带上包装,多少写进 desc。例:「一袋碎银」→ 钱袋 ×1,desc「装着些碎银」;「一把草药」→ 草药(一把)×1。
    ✗ 金币 ×1(一把钱被记成了一枚)  ✗ 因为数不清就干脆不记
  ✦ 转出先查【现有物品】:知道原数和用量 → update.qty 写剩下的总数;按包装记的 → update desc 写剩多少,qty 不动;确认全部给出或用完 → remove。
    ✗ 用正数 add 表示花掉  ✗ 用负数 add 代替转出  ✗ 原数未知时拿支出量、欠款或默认 1 反推余额
  ✦ 首次提到早就带着的东西不是刚获得,从口袋取出再放回不增减。库存里没有、本楼也没新得的东西,交易经过只写 summary(有未了义务才按计划规则记),不为记账 add;正文给出的余额只用来 update 已有条目,不当成本楼新增量。
【新增准入】默认不记。只有同时满足下列三条才记,缺一即弃:
  ✓ 主角实际获取并有意保留或支配(买、捡、收到、偷、制作、借入)
  ✓ 对剧情有意义(可交易/可使用/有情感价值/是线索/是武器装备)
  ✓ 角色会带走或专门存放的东西
以上三条已能排除绝大多数环境道具、日常用品、固定家具、普通食物饮料——这些都不满足"主动获取并保留有意义之物",无需逐一枚举。额外注意:
  ✗ 正在穿戴的服装、普通食物饮料(除非是关键道具/毒药/特殊料理)默认不记。当前穿着属于「即时状态」:{{user}} 写 protagonist.outfit,NPC 写对应的 npcs.outfit,不要当物品。
【消耗品处理】
  ✦ 已确认整条库存全部用完/喝完/吃完 → 用 remove 删除整个物品;只消耗其中一件不等于清空整组,按已知余量 update。禁止把普通残留物改成"空瓶""空盒"继续占条目。
  ✦ 部分消耗 → 用 update 更新剩余总量,不是填写消耗量;原数量未知时不猜,按包装记的改 desc 写剩多少。
  ✦ 普通容器随内容物一起删除;特殊容器(魔法瓶、名贵盒子)才单独记录。
【状态一致性】
  ✦ 物品状态只能因本回合明确描写的事件改变。
  ✦ 本回合未提及的物品 → 不写任何 items 指令,保持参考状态不变。
  ✦ 禁止脑补物品"恢复""补充""自动出现"。
【严禁重复结算(重要)】材料中的【现有物品】是结算到此刻的当前快照,【近期物品变动】是已经应用过的历史记录。
  ✦ 这些变动都已生效、已反映在现有数量里,绝不能再补一次。本任务基准是目标楼之前的状态,重摘仍从同一基准计算本楼一次,不要把目标楼旧旁注当作已结算而漏记本楼真实事件。
  ✦ 历史旁注、复制的变动格式和对旧变动的复述都不是本轮新事件;只依据本轮叙事中的实际行为。正文AI偶尔仿写物品变动记录也不能据此改库存;不要在 summary 中附加物品变动记录或旁注标签。
  ✦ 只有本楼新事件使数量、归属、保管位置或可用状态确有变化才写 items;获取/转出/消耗与寄存/取回/修复都按对应操作处理。新增准入不妨碍更新已有条目。
  ✦ 典型陷阱:上一段已把"解药 3→2",本段正文若没有再次饮用的明文描写,就保持 2,禁止再 update 成 1。
  ✦ 对照【近期物品变动】核对事件而非只核对物品名:同一次旧消耗不再处理;本楼若明确再次使用同名物品,是新的消耗,按本楼之前的数量结算。
【匹配】update/remove 必须用【现有物品】里的原名精确匹配。
【随身 / 存放地点(carried / location)】用于省 token:只有"随身"或"在当前所在地"的物品才会发给后续剧情,存在别处的暂不展开。
  ✦ 默认随身:角色拿在身上、随身携带的物品,carried 省略即可(等于随身),不必写 location。
  ✦ 明确寄存:物品被**明确留在某地点**(放回家中、存进宝库、藏在树洞、寄存柜台)→ 写 carried:false 且 location 填那个地点。
  ✦ location 命名务必复用材料中的【当前地点】或正文里出现的地名原文(如当前在"城西客栈"就写"城西客栈"),不要另造叫法,否则系统无法判断物品是否在身边。
  ✦ 移动物品:角色把存放的东西取回随身 → update 该物品 carried:true;把随身的东西放下/寄存某处 → update carried:false + location。角色仅仅移动位置、没动具体物品时,不要改物品的 carried/location。
  ✦ 寄存物品转移(A→B):某件**已寄存**的物品被从一处挪到另一处(仍非随身,如宝箱从地窖搬上马车、解药从甲房移到乙房,或被他人带去别处)→ update 该物品 location 改成**新地点**(carried 仍为 false)。物品换了地方却不更新 location,系统会一直以为它在旧处——这是常见漏更新点,务必盘到。
  ✦ 新获且明确携带的物品可省略 carried(默认随身);不凭空安排寄存地。已有条目去向不明时省略 carried/location,保持最后记录,不能用默认随身覆盖旧存放状态。

═══ 【场景/地点规则】(scenes 字段,只记到过的有名地点) ═══
地点树记「到过哪些地方、谁属于谁」;{{user}}此刻在哪由 location/locationPath 单独表达,当下局面写 sceneFocus,事件写 summary。
【何时建点】{{user}}实际到达有名字、而【已知地点】里还没有的地点 → scenes.add。只被提起、远远望见、路过一笔带过的地方,以及无名场所,不建。
  ✦ 判据不是尺度大小,而是剧情是否真在那个尺度上发生事:市井故事记到城市/街区就够,星际故事星球才有意义;不凭空往上堆国家/星球等空泛层级。
【路径分级】path 是由粗到细的完整路径,如 ["王都","城西区","归雁客栈"]。一条 add 写到最细一级即可,中间各级系统自动补建;某一级另有稳定特征可写时,再单独 add 一条带 desc 的。
  ✦ 上下级要有依据,以下都算:正文写明(「王都城西区的归雁客栈」);名字自带归属(「客栈的大堂」「3栋的302室」);移动过程表明在其内(穿过学院大门来到藏书楼 → 藏书楼在学院里);{{user}}在某区域内走动到达的新地点,未交代离开该区域时,挂在该区域下。
  ✦ 以下不算:先后到访不等于从属(从客栈走到码头,码头不属于客栈,至多与客栈同属城西区);相邻或望见;地名里的方向字(「城西客栈」不证明有个「城西区」);按常识或世界地图补出的上级。找不到依据的上级就不写,新地点可单独作顶级,以后查明再 reparent。
  ✦ 路径段用故事内地名原文,不用「这里」「某地」;同一地点复用【已知地点】的命名与层级,不换叫法重复建档。
【补层级(reparent)】已记录的地点后来查明从属于另一地点 → reparent 把它(连同下属)挂过去,不新建平行的顶级地点。
  ✦ 例:开篇只记了「家」(顶级);后来{{user}}出门走出「翠湖小区」大门,可知家在小区里 → 把「家」reparent 到「翠湖小区」下。
  ✦ 也能插中间层:已知「城西区 › 归雁客栈」,发现两者间还隔着「商业街」→ 对「归雁客栈」reparent,newPath = ["城西区","商业街","归雁客栈"]。
  ✦ node = 该地点当前的完整路径;newPath = 它应在的完整新路径(末段通常同名);descs 只给有稳定特征可写的新层级,可省。
【描述从严(desc)】建点宽,描述严:desc 只写有据的稳定特征(它是什么、结构/用途、与剧情相关的固定要素),一两句,客观不修饰;写不出就省略 desc 只建节点,不编、不凑。
  ✦ 天气、人群、路况、当次摆设、临检/管制、一次停留或遭遇等临时情况不进 desc,写 summary/sceneFocus;一次出现推不出长期用途,口述的特征保留来源(据掌柜称)。
  ✦ 只在地点本身实质变化(烧毁/改建/易主),或发生改变其意义的关键事件时 update,单纯重访不更新。update 整体覆盖,写累积后的完整描述:原「男女主初遇的咖啡馆」后来在此分手 → 写「男女主初遇、也是后来分手的咖啡馆」,不能只写分手。旧描述全是错填的临时状态时,desc 填空字符串清除,节点保留。
【当前所在(location / locationPath)】每楼都核对:本楼结束时{{user}}在哪?与【当前地点】不同就写 location,并同步 locationPath。
  ✦ location 是自由文字,可以很细(「302室屋内」「客栈后院井边」)。
  ✦ locationPath 是 location 在【已知地点】(含本楼新 add 的)里对应节点的完整路径,物品/NPC 是否在身边全靠它判断。对不上最细一级就退到能确认的上级:在客栈后院而树里只到客栈 → ["王都","城西区","归雁客栈"];只知在王都街上 → ["王都"]。真在两地之间赶路、连上级都确认不了时才给 []。
  ✦ {{user}}离开某处后默认仍在它的上级里(出了客栈仍在城西区),正文写明或明显离开该区域(出城、远行数日)才退出。
  ✦ 出发不等于到达:朝码头出发 → location 写「前往码头途中」,locationPath 给仍能确认的上级,不给码头;远远望见王宫不等于身在王宫;在途不沿用上一站。

═══ 【NPC 规则】(npcs 字段,极严筛选) ═══
{{user}} 本人不放进 NPC 名册;其变化写入 protagonist。NPC **默认不记**,门槛比物品更高 —— 宁可漏记,也绝不滥记;绝大多数楼层不产生任何 npcs.add。
━━ 准入硬门槛(必须满足其一,否则一律不记) ━━
  ① 该角色与 {{user}} 发生过**直接、具体且有剧情意义的互动**:有来有往的对话、冲突对抗、交易、结伴同行、情感往来、给予关键信息/物品等。一次性的服务性接触(点菜、问路、买东西、检票)**不算**互动。
  ② 或:虽暂未露面,但被剧情**反复指涉、明显重要**的关键人物(如尚未现身的幕后主使、被反复提及的传说人物)。
【反例】仅承担点单、带路、通报等一次性服务的角色,不因有名字就建档。职业不是排除标准:若同一人物后来提供关键线索、形成持续关系或满足上述②,按证据记入。
【判据】直接互动角色需有具体剧情影响及后续身份辨识价值;未出场人物按上述②判断,不强求已经与主角互动。拿不准时不新建,但不能因此漏掉已有角色的明确变化。
【字段】每个 NPC 可带档案层、即时层及独立的好感估计,更新门槛不同:
  ┃ 档案层(他是谁/长什么样,长期不变,高门槛,几乎不更新):
  ✦ gender:**性别**(短值,如「男」「女」)——记一次即可。**极重要**:性别在所有分档都注入(包括不在场),防你在后续剧情搞错该角色性别。首次记录时务必填,除非正文确实未透露。
  ✦ age:**年龄**——在正文**明确**提到时记(自报、被介绍、文档写明),写正文原话的值(「25」「二十出头」都行):名册里还没有年龄 → 补填;已有年龄 → 仅正文明确纠正/变化(过生日、改龄)才 update。**绝不要按时间流逝自己换算年龄**:系统会记下此刻的故事时间作锚点、以后随剧情时间自动推算;你若隔三差五重写一遍,反而把锚点刷乱。正文没提就不填,禁止按外貌猜。
  ✦ relation:**与主角({{user}})的关系**(覆盖型)——只写有依据的稳定关系称谓;可附持续且可观察的立场,不要求补一句态度凑格式(如「主角的师姐」)。未知就省略,一次合作不自动升级成长期同盟。
    目的地、行程、交易进度不写入 relation/title/desc:正在同行写 follow,位置写 location,末态行动写 sceneFocus,明确待办写 plans;有意义的经过写 summary。relation 不用作交易进度条:验货、还物、结账不因此刷新稳定关系。
    【质变的证据门槛(极重要)】真实关系质变只认三种证据:人物**明确说出**(公开断绝、当面告白定情)、双方**明确约定**(结盟、拜师、成婚),或**无歧义的客观事件**(一方杀了对方至亲、正式退婚)。
    ✗ 单次争吵、冷战、赌气离开、一次亲密举动、送礼、照顾、短暂分离,**都不构成质变**;事件写 summary,不据此断言决裂或和好。即时态度不硬塞入 relation,不得因缺席自动解雇或脱队。
    ✦ 持续立场只写有据的可观察事实,不把猜测的深爱或仇恨当事实。更新保留仍有效称谓,称谓确有变化才改。
    【字段纠错不是关系质变】旧 relation/title 混入临时动作或无依据内容时,允许 update 为有据的稳定部分,无需等到告白或决裂;不得顺带删真实身份/关系。确无可保留内容才用该字段的空字符串清除,省略仍是保持。已过期行程不迁回当前快照,即时字段须另按最新证据更新。
  ✦ ties:**与其他角色的重要关系**(高门槛)——只记长期结构性关系(血缘/婚姻/主仆/宿敌),一句话并列(如「阿黛尔之父;与镇长有旧怨」)。普通认识不记;对主角的内心好感与外在态度走 affinityInner/affinityOuter/affinityNote,不写 ties,不再新建对应的自定义变量。update 是整体覆盖,写累积后的完整内容;质变证据门槛与 relation 同。
  ✦ title:身份/职业一句话(如「旅店掌柜」「主角的青梅竹马」)——**最重要**,这是该 NPC 不在场时仍会保留的核心身份信息。
  ✦ desc:**固定外貌**——只写发色、身材、五官、明确永久或伤后遗留的疤痕等**长期不变**的体貌特征,**不要写当下穿什么**(那是 outfit)。
  ✦ personality:仅写明确设定或正文明确揭示的稳定性格,未知省略;不能从一次举动推断固定性格,更不能把当下情绪写成人格。
  ✦ 写不出 title 的角色基本没有记录价值,倾向不记。
  ┃ 即时层(他现在怎么样,会变,覆盖型,鼓励跟剧情刷新):
  ✦ outfit:**当前着装**。与 desc 分离正是为了解决「角色一辈子不换衣服」——**门槛低**:正文一旦明确描写换装、更衣、衣物被弄脏/撕破/血染/打湿,就 update outfit 写出当前完整穿着。它是最新有证据的快照;若换装或受伤本身构成关键事件,summary 仍保留其因果,不重复堆列整套衣物。
  ✦ condition:**当前状态/健康**(受伤、疲惫、中毒、醉酒、虚弱等);首次没有异常可省略,已有伤势按恢复证据更新,不可因本轮未提就清空。
【临时伤势与恢复证据】
- 临时不等于不重要:受伤、治疗、活动限制及影响行动的症状记入 condition;与伤情相关的绷带、夹板一并写在 condition,不写固定外貌或普通着装。稳定体貌未知就省略,不要用伤势填空;只有明确永久或伤后遗留的特征才进入固定外貌。
- 已记录的伤势在未提及、离场、重逢未谈伤情、时间跳跃或超过预计休养天数时均保留,没有新证据就省略 condition,不要清空、宣告康复或猜测恶化。记录是最后确认的伤情,不是断言离场期间一直如此;“自述还需休养几天”保留为估计,不是自动失效时间。闪回中的健康不能覆盖当前伤势。
- 每次更新前,对照旧记录中的伤处、症状/固定措施、活动限制和休养估计;本轮只新增休养估计,不能挤掉尚无解除证据的活动限制。输出的是整段新状态:尚无解除证据的旧内容原样保留,有明确变化的只改对应部分,确已恢复的才删去(须有本轮正文依据,时间流逝或闪回中的健康不算);新估计取代旧估计时只留新的,不累积互相矛盾的天数。
- 首次记录没有旧伤情时写 condition;已有伤情时,整段新状态里保留其他尚未解除的伤情和限制。拆绷带、能走路等只更新明确证实的变化,不等于所有伤势痊愈;明确全部恢复或旧记录被证实错误才清空。不借恢复一处清掉所有限制。
- 伤势进入状态字段不代表从摘要删除关键受伤事件:造成行动改变的受伤、治疗和恢复仍可简短记叙;之后无需每楼重复外观,历史受伤与当前已恢复可以并存。
【外貌、着装与伤情分开】「黑色长发、左眉留有永久伤疤」→ desc;「今天穿红斗篷、佩长剑」→ outfit;「手臂受伤,夹板固定,暂不能提重物」→ condition。刀鞘、佩刀等当下装备不属于固定外貌。
【纠正错填外貌】若既有 desc 混入绷带、临时伤势或当下装备,update desc 只保留有依据的稳定体貌;若没有稳定体貌可留,明确输出 desc:"" 清除错填。desc 省略=保持,空字符串=明确清空。清理 desc 不代表伤势康复,也不能仅凭旧 desc 把已痊愈伤势重新写回 condition;迁入即时层须与已有状态及本轮证据相容,不臆造状态。

【主要角色(important)—— 核心主演的状态追踪】
  ✦ 何为主要角色:在剧情里**反复出场、戏份吃重的核心主演**(常驻主角团、主线关键人物)。它们的身份/性格/外貌设定通常已在角色设定里,**无需你费笔墨记档案**。
  ✦ 标记:认定某角色已成为主要角色 → 在其 add/update 里带 important:true。也可能由用户手动标记。
  ✦ 主要角色按完整档案候选进入后续记忆(不受在场与否影响,但仍受注入预算约束),所以对它们**重点维护即时层**(outfit/condition/location),title 给一句帮定位即可,desc/personality 可省。
  ✦ 不要滥标:绝大多数 NPC 是配角,important 省略即可;只有真正的核心主演才标。
【随行 / 所在地(follow / location)—— 省 token 核心】只有「随行」或「在当前所在地」的 NPC 才会把完整信息发给后续剧情,其他地方的 NPC 只发名字+身份。
  ✦ 定点(默认):NPC 待在某地点 → location 填那个地点(复用【当前地点】或正文地名原文),follow 省略即可。
  ✦ 随行:NPC 作为同伴**跟随主角一起行动/赶路**(队友、随从、暂时同行者)→ follow:true(此时不必写 location,随主角移动;**也不要写 location:""**——空串只表示所在不明,不是“没有地点”)。
  ✦ 移动 NPC:某 NPC 加入队伍同行 → update follow:true;同伴离队留在某地 → update follow:false + location 填留下的地点;NPC 自己从一地去了另一地 → update location 改成新地点。
  ✦ 离场但去向未写明(正文只写告别/离开场景,没说要去哪)→ update follow:false + location 填空字符串 ""(表示所在不明,系统**不再**视为在场);绝不能保留旧地点冒充还在原处。**离队必须写 follow:false**:系统绝不会仅凭空 location 取消随行,只写 location:"" 仍按随行处理。之后正文说明去向时再 update location 填新地点;重新同行 → follow:true。
  ✦ location 命名务必复用既有地名原文,否则系统无法判断 NPC 是否在场。
  ✦ 首次记录:正与{{user}}当面互动的 NPC,location 通常就填{{user}}本楼所在地点(复用 location 原文);一同行动的写 follow:true;只被提起、通话或传信联系的角色不算同处,正文没交代所在就省略 location。
【何时更新(update)】
  ✦ **在场核对(每楼必过)**:名册每条带〔在场〕/〔同区域〕/〔不在场〕标记(系统按**本楼开始前**的状态算好)。逐条核对:NPC自己离开/告别 → 更新 location 或 follow;仅主角换景、定点NPC未同行且无新消息 → 不重报旧 location,让系统保留最后确认。标〔不在场〕的角色本楼明确重逢 → 更新回在场(follow:true 或本楼所在的 location)。更新位置后,同步把 sceneFocus.participants 改成与实际在场名单一致(冲突以正文为准),不要两边各说各话。
  ✦ 档案层(title/desc/personality):只在**发生实质变化**或**首次补全**时更新;普通互动、对话不更新。update 的 desc/title 是整体覆盖,要写累积后的完整内容,别丢旧要点。
  ✦ 即时层(outfit/condition):门槛低,正文描写了换装/受伤/状态变化就 update,这是它存在的意义。
  ✦ 清空语义:省略 outfit/condition=保持旧值;填空字符串=清空(outfit 脱下/condition 完全恢复)。condition 只删去确已恢复或结束的部分,其余照抄;本轮未描述不等于状态消失。
【离场后的证据边界】
主要角色与配角使用同一事实标准:没有新证据时不得推演位置、换装、痊愈或恶化。旧快照是最后确认记录,不是保证持续到现在。
跨场景、明确跳时后,未再次确认的位置只能作历史参考。再次被提及不等于再次在场;重逢只更新此次明写的状态,不得靠楼层数猜经过多久。
【退场(remove)】NPC 永久退场(死亡、彻底离开剧情且不会再出现)才 remove;只是暂时分开、去了别处用 location/follow 表达,不要 remove。
【复用已有,严禁重复】材料中的【已登场NPC】是已记录名册。同一角色务必复用既有名字,不要换个叫法再记一遍;已在名册里且无变化 → 不输出 npcs。

═══ 【内心好感与外在态度规则】(NPC 对 {{user}} 的稳定倾向估计) ═══
【有限估算例外】仅 npcs.add/update 的 affinityInner、affinityOuter、affinityNote 允许结合已知人设、此前状态和本轮剧情自动估算;其他字段和 summary 仍只记有依据的事实。估计不是已证实的内心,不得把它抄入 summary/relation/ties/personality 或据此确认关系、伏笔、动机。
【五档,不是分数】两侧各自只接受整数 -2、-1、0、1、2,含义如下:
  内心好感(affinityInner):-2=强烈反感;-1=不喜欢;0=无明显好恶;1=有好感;2=感情深厚
  外在态度(affinityOuter):-2=明显敌对;-1=冷淡疏远;0=不明显亲近或排斥;1=友善亲近;2=明显亲近、积极表达
  内心好感=对 {{user}} 的真实好恶/在意与亲近倾向;外在态度=对 {{user}} 相对稳定的对待方式(不是对所有人的态度),不是本轮一句话的语气或心情。两者都不等于爱情、信任、服从或同意。爱恨交织不能正负抵消成中性,矛盾写在说明中。
【未知与补丁】尚无依据的一侧保持未知,不要默认填 0。首次有足够依据时可单独初始化任一侧;其余时候省略字段=沿用旧值,null=明确撤回不可靠估计并恢复未知。旧记录没有字段也不要求补齐。档位是绝对状态,禁止增量、百分制、小数或暗中累计分数。
【默认保持,跨档才更新】从旧档位出发,不是每轮重新打分。只有新剧情足以说明旧档位不再合适才改:持续清晰的新倾向、重要触发事件或对旧判断的明确纠正。变化越大,依据须越充分;重大转折可跨档,没有固定每轮增减幅度。没有变化就完全省略好感字段,不能为了完成盘点强行制造变动。
  普通夸奖、送礼、亲密举动、拌嘴、一次冷脸或开心通常不跨档;一时情绪写 summary/sceneFocus 的明确事实,不要改写长期感情。小事件可构成发展过程,但不能每次结算;旧摘要复述、聊天轮数、时间流逝、旧档位本身都不是再次变化的证据。
【内外完全独立】分别判断有无变化、方向与幅度;内变外不变、外变内不变、反向变化、两者都不变均可。不预设内慢外快,不设联动、自动追平或固定人格增长系数;表里如一也不强制绑定。人设影响他在意什么及如何表达,不是见到“傲娇/虚伪”就自动套档位。仅凭客套或嘴硬不能确认内在;要结合行动、上下文与已知设定,证据不足则不改。
【说明也要稳定】affinityNote 是一句简短的依据/表现/矛盾说明,不是内心独白或新增剧情。同档默认沿用旧措辞,禁止每轮升级修辞来暗中加深感情;只有跨档或依据、表现机制、旧判断确有实质变化时才更新。只改一侧时说明仍须与另一侧的既有状态相容。空字符串可明确清空错误说明。后来揭示一直在伪装,是修正旧估计,不要记成这时突然变心。
【输出示例】若原内=1、外=-1,本轮重要事件支持内在升到2而仍掩饰,只写 {"name":"原角色名","affinityInner":2,"affinityNote":"估计更加在意,仍以冷淡掩饰关心"};外在不重复写。若只是普通互动,两侧与说明均省略。
【分工与视角】relation 保留关系称谓与可观察立场,ties 保留长期人际结构;内置好感不写入自定义变量,不要据此新建或同步同名变量(用户已有变量仅按其原规则独立处理)。内在估计不代表主角或其他角色知情,不可让人读心、揭穿秘密或自动表白。

═══ 【计划/悬念规则】(plans 字段) ═══
分"计划"(plan)和"悬念"(suspense)两类。新增共同铁律:【默认不写】。只有确信一件事必须被长期记住、否则会损害后续剧情,才新增。绝大多数楼层不产生任何 plans.add;这不免除已有条目的核对。
━━ 每楼先核对旧条目,再考虑新增 ━━
按本楼明确的新决定与结果逐条检查【未了结】,选一种处理,不是等正文出现“取消”二字才核销:
  · 仍有效、未提及或结果未明→省略,不得因离场/过期/时间流逝自动结案。
  · 同一事项改期、暂缓或改变执行条件→plans.update:{ "id":"p1", "content":"保留主体与仍有效目标,写清新的安排/暂缓及有据的恢复条件", "targetTime":"有据的新期限" }。content整体更新,不删仍有效义务、不虚构恢复条件;未改期限省略targetTime,未定期限用空字符串清除。继续open只表示未了结,不表示现在就要执行;不另add同一事项。
  · 明确决定替代旧方案且不再执行旧方案→旧条目resolve cancelled,reason写清替代依据;新方案只有满足新增门槛才add。仅讨论备选、试探或暂缓不等于永久放弃。
  · 实际兑现、真相揭晓、明确失败,或已彻底不可能再发生(如约定的对象已死)→按下方outcome结案。同一编号每楼只做一次update或resolve,不可两者同时输出。
【update 的 content 怎么写】content 是整段替换,不是追加半句:
  · 把旧 content 按条款拆开,只改本楼有新说法的那条,其余仍有效的照抄;新增的条款另起一句,新条件只挂在它对应的后果上,不挪给旧条款。
  · 只删明确撤销的条款;旧记录与本楼原文冲突时按本楼原话改,没有原文依据就保留分歧,不猜着修。
  例:旧「三日内还清 50 金,逾期扣押马车」,本楼债主同意宽限到七日 → content「七日内还清 50 金,逾期扣押马车」(只改期限,后果照抄),targetTime 同步改。✗ content 只写「宽限到七日」(欠款和后果都丢了)。
先分清计划范围:停止一次尝试不必取消总体目标;改变手段也不等于目标已经完成。原条目若只针对已被替代的手段,不能继续原样挂为当前待办。
━━ 准入第一关:跨场景存活测试(最重要) ━━
问:"这件事会在接下来一两个回合的自然推进里得到结果吗?"
  会 → 不写。它只是当前还没写完的剧情,交给 summary 即可。
  只有需要【时间跨度】或【外部条件】才能解决的事,才可能进入。
反例(会很快兑现 → 一律不写):女主犹豫念不念情书、有人敲门、对方欲言又止、检定待揭晓、"他会怎么回答"、单纯沉默/离场、普通等待赶路、普通寒暄约饭。
正例(跨得过当前场景 → 才考虑):三日后决斗、毒药七天后发作、铁匠承诺改日打造武器、某组织正在暗中追查。
━━ 计划专属:意图真实性测试(过滤敷衍/客套/口嗨) ━━
过了第一关也别急着写。再问:"说话人是认真要去做、还是只是随口一句?"——只有【真心、当真的承诺/打算】才算计划,社交辞令和敷衍一律丢弃。
判断依据(只看文本明写的,不脑补):有无具体对象/时间/条件?是否被反复确认或郑重其事?后续言行是否当真?语气是认真还是打发、客套、嘴上应付?
反例(敷衍/客套/口嗨 → 不写):"下次再说吧""改天一定""有空一起吃饭""以后再聊""回头看看"等用来结束话题或客气的话;一时冲动的气话、酒后随口、明显的玩笑或反讽。
正例(真心当真 → 才考虑):明确约定了时间地点的会面、郑重立下的誓言/赌约、为兑现已开始做准备的承诺。
证据不足时不建计划,但不能在摘要里判定对方敷衍;需要保留时只记其说法和未确定性。
  · "计划"= 正文明确给出行动主体【真心】决定、承诺、约定要做的未来行动。无论主体是 {{user}}、角色还是 NPC,只要重点是"这个人打算做什么",都归计划。
━━ 悬念专属:类型准入测试(必须命中一种,否则不写) ━━
悬念簿是【待揭晓事实 / 已启动外部事件】清单,不是剧情笔记、人物心境档案或设定摘抄。候选 suspense 只允许以下两类:
  A.【待揭晓事实】正文明确留下未知的身份、动机、来源、去向、真相或异常原因,并给出具体的异常、线索、隐瞒或相互冲突的证据。未知点必须由正文提出,不能由你自行制造"也许还有秘密"。
  B.【已启动外部事件】某个不以角色口头承诺为核心的外部进程已经实际开始,并朝具体结果推进,后续等待其客观结果。例如追捕已经展开、毒药进入倒计时、触发条件已经成立。仅仅具备能力、存在弱点或有可能发生危险,不算事件已经启动。
【绝非悬念】以下内容即使重要、长期存在、尚未解除,也不得写 suspense:
  · 已经解释清楚的世界观设定、能力机制、仪式规则、代价、副作用;
  · 伤势、诅咒、灵魂绑定、无法攻击某人等持续状态;
  · 人物的内心挣扎、感情纠葛、身份/职责矛盾、关系张力;
  · "存在弱点""可能被利用""构成潜在威胁""埋下隐患""矛盾将持续";
  · 只是尚未改变/解除、但没有未知答案也没有推进中外部事件的事实。
这些内容需要保留时写进 summary、人物状态或其它对应字段,不得包装成 suspense。
【禁止万能疑问】不得仅用"X会不会Y?""将如何收场?""未来会造成什么后果?"把已知状态改写成悬念——任何持续状态都能套这些句式,它们不能证明存在悬念。
【content 写法】只写一两句客观的【已知关键事实 + 精确未决点】或【已启动事件 + 待定结果】;禁止抒情、剧情评论和"潜在威胁/矛盾持续"式收尾。
━━ 新增前查重:按未知答案/待决事件归一 ━━
写任何 plans.add 前,逐条核对材料中的【未了结】与【近期已了结】条目:
  · 把已有条目与候选 suspense 各自归一为"等待揭晓的答案是什么"或"等待结果的同一个外部事件是什么"。
  · 若答案会同时揭晓,或本质是同一个事件的结果 → 同一条,严禁 add。新线索、规则细节、阶段进展、佐证、人物反应与两难只写 summary,不另建悬念。
  · 仅仅根源相同不必强行合并:若未知答案不同、可各自独立揭晓,或确是两个独立外部事件,才可分别记录。
  · 已了结条目禁止换个说法重新 add。拿不准是否重复 → 视为重复,不写。
【悬念核销预检】新增前先设想未来如何 resolve:必须能写成"未知答案揭晓为……"或"已启动事件的结果为……"。如果只能写"这种状态后来消失/改变/缓和了",它就不是悬念。
【核销/了结】plans.resolve 每项都要写清**怎么了结的**,格式:{ "id":"p2", "outcome":"done|cancelled|failed", "reason":"一句话:关键事实+结果" }(id 用【未了结的计划/悬念】里的编号如 "p2")。
先问一句:"文本是否明确说明此事已解决/揭露/兑现/失败、已彻底不可能再发生,或原方案已撤回、被替代而不再执行?"——是且有依据→resolve;只是同一事项的条件变化→update;否则保留。悬念不因时间流逝自动消失。
outcome 三选一,务必分清:
  · done=计划真去做成/兑现了、悬念真揭晓了(结果/答案已明确);
  · cancelled=**没做成,而是被取消、撤回、放弃、作废、不再需要**(对方收回要求、情势变了、当场被化解退让等);
  · failed=尝试过但失败,或悬念以坏结局收场。
reason 必填一句,写清「为什么了结 / 如何收场」,只写这次实际的结束方式:不照抄已失效的惩罚条款,不为解释完成而增加未明示时差或新的付款/履约动作。⚠️最易错的坑:一件事「**被提出后又当场被化解、对方退让、承认搞错、不了了之**」→ 这是 **cancelled(取消/作废),绝不是 done**;reason 要写出「所以不用做了/此事作废」,否则后续会误判它仍然有效、仍需执行。
【计划时间】plans.add 的 createdTime 只填有依据的立下/出现时间,保留已有精度;无依据可省略,不得补造日期;计划(plan)还应带 targetTime(打算去做/兑现的目标时间):
  · 有明确期限→写具体时间(如"放学后""1988/10/1");
  · 是泛泛的愿望、无明确期限(如"以后有机会一定要去看看")→targetTime 可写模糊描述或直接省略该字段。
  · 悬念(suspense)通常没有目标时间,可省略 targetTime。

═══ 【互动局势卡规则】(sceneFocus 字段,覆盖型单对象) ═══
它是「眼下正在发生什么」的一小张快照,帮写作 AI 衔接当下场面;是续写起点,不是第二份摘要。整卡覆盖语义:
  ✦ 省略 sceneFocus = 保持上一张;写 null = 明确清空(场面彻底结束/章节落幕才用)。
  ✦ 要写就写完整一张卡(不是补丁):situation + participants 必填,其余可选。
【更新时机】满足任一就更新,否则省略:
  ✓ 场面/在场人实质切换(换场地、有人进场离场、从闲聊转入正题)
  ✓ 当前活动实质转移(开始商量新的事、进入新活动)
  ✓ 互动张力出现或解除(开始冷战、气氛缓和)
  ✗ 同一局面里的普通推进(一句话一个动作)不换卡——那是 summary 的事。
【字段口径】
  ✦ situation:本楼结束时的局面,一句话为主,可在句中自然带出此刻围绕什么进行。陪伴/日常剧情写互动氛围(「午后同居日常,她情绪有点低落,正教 {{user}} 做菜」);剧情向写处境(「潜行中,刚被巡逻队发现」)。仍卡着下一步的阻碍可以补一句。
    ✗「先到酒馆打听消息,又跟老板讨价还价,现在……」(把经过塞进卡里)→ ✓「在酒馆柜台跟老板压价,老板咬死不松口」
    ✗「得知北门已封」(把听来的写成确认)→ ✓「据守卫称北门已封」。所见写所见,口述写「某人称」,判断写「某人认为」;要删先删次要内容,来源、否定和适用范围不删。
  ✦ participants:当前在场参与者(含主角,用 {{user}});远程联络、回忆、被提及不算在场,远程交流可在 situation 说明,已离场的人不在卡里占位。必须与 NPC 名册的〔在场〕标记一致:更新 NPC 的 location/follow 后,同一条 delta 内同步修正 participants(以正文为准)。
  ✦ tension:互动张力,高门槛。只有明确的、正在持续的社交张力才写(冷战/尴尬/暧昧暗涌);一时的语气变化、普通情绪波动不写,危险或行动难度本身也不算。无则省略。
  ✦ pendingBeat:即将发生之事,仅限正文明确预告/约定/已启动等待结果的(「她刚起身说去开门」)。禁止预测未发生剧情;只是把 situation 换成将来时的不写(situation「正收拾行李准备出发」→ pendingBeat「即将出发」✗)。无则省略。
【克制】本卡与 tension 是写给写作 AI 的隐性氛围约束(别在冷战时写成腻歪),不是点名要求;正文自然体现即可,严禁复述或点破本卡内容。

★ 纯叙述句,不要标题、列表、加粗等任何 markdown 标记。

═══ 【关系线保留】(摘要与压缩共用,不可当作重复日常删除) ═══
人物关系的发展常不靠大事件,而靠一串可观察的小互动:靠近与身体接触、主动照顾或维护、承诺与约定、称呼与语气的持续变化、送礼、玩笑、回避、沉默、争执与和好。
  ✓ 这类**具体动作与关键台词**,即使不推动主线、不改变任何档案字段,也必须保留其具体语义,不得以“没有新事件”为由压缩掉;同类互动可以合并。
    例:保留「她把椅子挪近,手搭在他手边」「他承诺不会让她吃亏,她没接话」,而不是删成「两人聊了几句」。
  ✓ 压缩跨时段时,同类互动若构成可观察的趋势,用「自X起……」概括保留并带代表性细节,不得作为“重复的亲密互动/调情”整段删除;合并时保留区别于旧互动的新动作、回应、拒绝或条件。
  ✗ 关键承诺、拒绝和带条件的话保留短原话或等义转述;“手放在手边”不能升级为牵手,“不会让你吃亏”不能升级为表白。不得只留“日常相处”“关系有所变化”等空泛概括;也不得把互动改写成“感情升温”“关系恶化”等心理或关系结论——只记可见事实,证据边界不变。

【摘要成文顺序】
- 先选事件,再写句子:以目标、阻碍、转折、结果及仍有效的约束为取舍依据,不是按原文每句各缩短一次。这是取舍顺序,不是必须填齐的叙述模板;没有转折或结果就不编造。
- 【先选后写】先确定本次新增的关键结果、选择、有效限制和关系证据,再补能解释这些变化的必要前因与仍有用途的明确情报。每个事件写清变化即可,不为覆盖原文段落或填满字数追加动作。已入选的技术情报保留适用的数值、条件、触发风险与时间窗口,不能用“核对完毕”代替。
- 留下动作不等于留下信息：对每个细节问，删除后是否改变事件结果、行动选择、有效限制或关系边界？不改变则整项删，而不是换一个更短的动作说法。没有提供具体参数的核对/检查不算新增情报;历史衣着若不用于识别或对照则删;闪回只留解释现状的往事结果与必要差异,不以“曾出现过”为保留理由。
- 同一事件只写一次关键结果;反复取放、检查、收纳物品不是多次新进展。装饰、材质和摸口袋、扣扣子、折叠收好等保管动作,若无失窃/转移/保管争议则整组省略,不改写成一句“确认仍在”继续占位。关键新得失、约定与了结保留。不能用本规则抹掉临时伤势、否定或【关系线保留】要求的具体互动;也不把某个情感动作扩成整组无关收场细节的保留理由。
- 按剧情先后把状态、比较基准和限制放在对应阶段,不强制前置或套固定句式;无相关事实就直接写事件。保留主体、关键手段、结果、了结与必要因果;中途变化不得提前套用于更早阶段。
- 选定关键事实后用完整短句成文,保持单段自然叙述,summary 内不加标题或列表。允许必要的主谓与连接词,避免“进行了/表现出/体现了”等空泛记录句;不要为多塞细节而删虚词、堆分号或括号写成电报,不扩写成小说。有证据才用因果连接词。
- 篇幅是上限而非填满任务。在本任务篇幅内先压缩重复过程和修饰,不让动作细节挤掉关键事实及其限定。超长时先删低价值事实,再合并同一事件,最后精炼句子;不能通过删否定、条件阈值、来源、时段或因果路径缩短,更不能把不同条款拼成扩大责任的新约定。

【空间事实边界】
分段移动按先后保留;不得把多段方向合成一个新方向,也不从起终点计算未明说的路线。方位词连同被修饰对象和参照物一起取自材料,只修饰原句对应的对象,不借给邻近物体或后续路过的设施;参照物不明就不补方位,也不用常识、地名中的方向字或行进目标补出方位。目的地不等于已到达;看见、邻近、出发或到访顺序不证明地理包含。离开局部空间不等于离开上级区域:出门、消失在视野中不自动成为离楼、离城或离队;只记录明确离开的最小范围:{{user}}默认仍在其上级区域内,他人离开视野而去向未写明就保持未知。没有同一地点证据就不把两个名称合并。路线信息可删次要段,不能将保留的方向、距离或风险挪给另一段。没有本次位置证据，就不在摘要末尾补写离场者仍在旧处；确需解释分开行动时写“此前表示留在某处”或有据的最后见面时间，不把留守打算写成持续实况。未同行也不证明去了别处，伤势不能因离场被删除。
【命题原义传递】
- 先分开亲见、某人所述、依据迹象的推断与已决定的行动,再把来源和限定随命题一起保留。改述不能增加确认程度:相邻亲见事实只证实它自身,不能替旁边的口述背书,也不用“得知/确认”给未经核实的口述或预测背书。后文证实只从后文时点更新,不回写此前已知。
- 最小合并单位是完整命题：主体/来源、条件、后果、对象和适用时段一起保留。共享条件不代表共享后果,多条约定逐条保留各自“条件→后果”的对应(见下方条款更新示范)。更新或融合时按后果及其适用对象定位：旧条款未被明确替代就独立保留；新增的后果另起分句,新条件不分配给旧后果；明确撤销或替代的只更新对应条款。省略共同主语可以，省略各自触发条件不可以。
- 同句并列不证明同行、归属或因果。等待某人与某批人到来同时出现，不足以证明该人属于该批人；空间相邻也不补隶属关系。不影响后续的并列细节可删，不用新的关联词把它们强接起来。
- 条款按“触发条件→影响对象→具体后果→适用时段”核对。此前/此后、当次/后续、部分/全部、已发生/将发生逐词对照,不可互换:取消未来合作不等于撤销既有交易,“此后批次取消”不等于“此前批次取消”。条件中的程度、门槛和适用范围不可删,不可将达到特定损害程度压成任意损害。对象含糊时保留原短语，不自行解释成欠款、退款、免债或履约;原义明确时写具体对象与结果，不统一套成笼统财务术语。
- 概率、程度与证据强度既不增强也不弱化:极可能≠可能,似乎≠确定,极少≠零,几乎≠绝对,至少≠约,到达阈值≠超过阈值;保留原有至少/至多/仅/仍/尚未。依据迹象或物证的判断仍写“据…推测”,不把物证的存在变成某人确实做过某事;推测、可能、声称、打算不升级为事实或完成。
【关键短语保真】
- 对已经选中的事实，先从材料复制关键短语，再压缩周边叙述，禁止凭记忆另写一套近义表述。条件、对象、后果与时段作为一组，来源、程度和否定随之保留；不是先收集相似关键词重组成句。
- 压缩可以删掉非关键命题,不能改写剩余命题的关系。核对行动者、对象、条件、媒介或路径、结果仍各归其位;地点及旁边的设施不能被改成动作主体或致因。
- 一项机制若值得保留,就写清必要路径与条件;放不下时删低优先细节,不要省掉关键中介后强连因果。数量、时限和否定必须仍修饰原来的对象。
- 保留时间适用范围:当日临检、眼前所见不升级为长期规律;局部否定不扩成全面完好,“未受新损伤”不等于从无旧痕。

【表达示范,不是剧情资料】
- 条款更新：旧记录“泄露资料则终止后续合作”；新材料“泄露资料或迟交则扣本次补贴”。更新后：泄露资料则终止后续合作；泄露资料或迟交则扣本次补贴。不能写成“泄露或迟交则终止合作并扣补贴”；只有新材料明确替代旧条款才删旧句，不要把“若…则…”擅改为“只有…才…”。
- 取舍前：“他反复核对封套花纹，取出文件看了又收好，检查搭扣，手伤仍不能负重；因现场受限，取消当面提交，决定改为远程提交。”取舍后：“现场受限，他取消当面提交，改为远程提交，尚未执行；手伤仍不能负重。”只示范取舍，不把动作细节改写成“确认无误”保留。若原文给出“低于四十单位才可启动，启动前须断开备用电源”，有用的数值与前置条件仍须完整保留。
- 了结：“设备提前归还并验收，旧约定有迟还惩罚”→只写归还及验收结果，不附加一遍旧惩罚。
- 位置与并列：“队友退出实验室，准备去观测站”只支持离开实验室，不证明到站或离园。“维修队下午进楼，她等朋友”不证明朋友在维修队中。
- 只借用取舍和表达方法，不复用人物、物品或情节，也不带入示例的数值或规则；以实际输入为唯一事实来源。

═══ 【摘要时间语言铁律】(summary 等文字叙述中的时间写法,强制) ═══
- 有可靠时间锚点时,把“明天/昨晚”等换算成固定日期;不得抹掉已有明确时间。
- 无法换算时保留绑定具体事件的相对关系,如“约定在这次会面次日再来”,不能为了去掉相对词而编日期或删约定。不要用随阅读时点漂移的“今天/明天”作无锚叙述。
- 叙述沿用输入的时间精度与确定程度:推定/未确定不得写成已证实时间,不补原文没有的年份、分钟。
- 段落起止是范围，不是每个事件的发生时刻:09:10—09:40 是整段范围，不能把未标时的离开写成 09:40 离开;要标时间就把范围放在整段前，事件本身另有明确时点才单独写。本段有明确时间标签时，不拿上一段末时或输入的旧当前时间代替；不把分钟向整点取整。事件自身明写的时间归该事件，回忆、期限不充当主线时点。普通事件可按任务粒度省略时分；需要时分却无法定位到一点时保留范围，不任选端点。
- 闪回、回忆与当前主线分清,不把后来揭晓的信息写成当时已知,不把叙述顺序当作事件时间顺序;闪回不刷新当前状态。
